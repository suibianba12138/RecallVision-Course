02 / APPLICATION ARCHITECTURE

Video processing and trusted retrieval

V2 connects earlier computer vision modules into a single local application. The difference from V1 is not a new detector: it is the ability to analyze another input, inspect uncertainty, revise evidence and reopen stored analyses.

01 — ANALYZE

Import & process

Upload a supported local video (up to 250 MiB and 120 seconds) or reopen a saved run. YOLO11n, ByteTrack and the memory pipeline produce recorded candidate objects and events.

02 — EXPLORE

Inspect & correct

Browse object candidates and video frames; review identities, exact observations and movement candidates. Choices can be revoked, and unsupported information remains uncertain.

03 — ASK

Trusted historical QA

WHERE, WHEN and WHERE-BEFORE read reviewed memory and provide frame/time references. Without sufficient reviewed evidence, queries explicitly withhold unsupported answers.

Important distinction

V2 supports a reviewable workflow; it does not prove that automatic perception and event interpretation are reliable on arbitrary new videos. Human confirmation is part of its trusted-answer contract.

INDEPENDENT VIDEO EVALUATION

Observed limitations

E1 CAPABILITY EVALUATION
0/5 annotated targets

Automatically resolved target objects across four independent evaluation videos. The original YOLO11n category vocabulary could not cover several required objects, and identity fragmentation remained.

FALSE MOVEMENT CANDIDATES
4 visually confirmed

Automatic accepted movement candidates were false positives in E1; V2 preserves candidate/review separation to avoid presenting unsupported movement as fact.

Scope

V2 implements the Analyze → Explore → Ask application and a human-review trust layer. The independent E1 results show that automatic new-video task success was not established. No browser visual acceptance screenshots were produced for the frozen application.
