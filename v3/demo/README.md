# RecallVision V3 Course Demo Pack

This pack restores memory generated by completed RecallVision V3 runs for three real Mixkit clips. It contains source URLs, expected SHA-256 hashes, saved memory records, exact evidence-frame references, and one real cached answer per clip. It contains no MP4, screenshot, SQLite database, or model weights.

The source pages currently mark these items for the Mixkit Stock Video Free License and describe them as free for commercial or personal use. The license page also points to the Mixkit User Terms. The repository therefore references the official item pages and asks the presenter to download the clip directly rather than republishing source media here.

## Prepare the clips

Download the HD Ready 1080×720 version manually from each official item page and save it with the listed filename. The importer validates the exact source hash and refuses a different encoding or variant.

Place the three files in a local `demo-media/` folder. Optionally check hashes before restore:

```bash
sha256sum demo-media/*.mp4
```

## Restore the saved demo memory

Activate the RecallVision Python environment from the root README, then run:

```bash
python scripts/import_course_demo.py demo-media/mixkit_101309_720.mp4
python scripts/import_course_demo.py demo-media/mixkit_100072_720.mp4
python scripts/import_course_demo.py demo-media/mixkit_43699_720.mp4
```

The command copies each verified video into the local persistent store, restores its real memory records and saved answer, and decodes the saved evidence frames from the supplied source file. It does not invoke Qwen, TimeLens2, or Grounding DINO. Running the same restore again is idempotent. If that video already has a different completed analysis, the importer preserves it and asks for the explicit `--replace-existing` option.

Start the app as usual and select each `Course demo` entry under **Or reopen a saved video**. Normal new-video use remains separate: choose **Choose a video** to run a fresh analysis.

## What to show

- **Backpack:** ask `Where did I leave my backpack?`. The saved result reports a reference-matched backpack candidate in the middle-left of a sampled frame at about 4.96 s. Later sampled checks are `UNKNOWN`; this is not an exact disappearance time or a real-world location.
- **Tablet and mug:** ask `What objects appeared in the video?`. The saved answer lists a black tablet and blue-speckled mug as model-generated, `UNVERIFIED` candidates.
- **Plant:** ask `What happened to the plant?`. The saved answer presents the plant-pot interaction as an `UNVERIFIED` event candidate, with sampled source times rather than a precise event boundary.

These answer strings and statuses are stored in [`course_memory_pack_v1.json`](course_memory_pack_v1.json) from the real local runs. They are not generated by this document or hard-coded into the app. Check the evidence frame in Explore or Ask before describing any unverified claim as fact.

## Data boundaries

The memory pack excludes original videos, database files, evidence images, and model weights. Restored data and locally decoded source evidence stay in the configured persistent-memory directory. The pack is tied to exact hashes; a different video variant is rejected so that saved timestamps cannot silently point at the wrong source.
