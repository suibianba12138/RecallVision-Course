03 / SYSTEM WORKFLOW

Memory-backed retrospective questions

The application separates semantic hypotheses from corroborated source-frame observations. Cached answers can be reused across restarts; first-time model inference remains CPU intensive.

01 · ANALYZE
Construct memory

A local VLM samples timestamped frames and proposes scene, entity, and event records. SQLite saves source metadata, model provenance, and evidence references.

02 · EXPLORE
Inspect evidence

Browse saved objects and event candidates, verification labels, and exact sampled source frames. Detector misses remain UNKNOWN rather than automatic absence.

03 · ASK / REOPEN
Retrieve and reuse

Search stored memory before using targeted evidence checks. Reopen saved videos and previous answers without regenerating completed memories.

04 / EVALUATION AND RELEASE SCOPE

Documented application results

RC1 demonstrated restoration of 24/11, 11/6, and 11/8 memory/evidence records across the three clips, with measured import times of 2.160 s, 0.659 s, and 0.713 s. Focused release testing reported 61 passed; the public lightweight source checks are separate. The source full suite reported 530 passed, 5 skipped, 2 deselected, and 3 legacy V2-environment failures.

The source videos are short (8.88–11.72 s). Initial CPU memory generation took 202–272 s; browser visual QA, general long-video understanding, reliable action boundaries, and precise identity continuity were not established.
